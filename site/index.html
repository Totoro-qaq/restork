EFFECTS ARE NOT PROMISES

Preview before every write.

An agent that writes a file without asking is an agent that cannot run on your real notes. Restork shows you exactly what will change, bound to that precise content, and only a single-use approval makes it real.

01

Markdown stays ordinary

Point Restork at an existing Obsidian Vault or a separate folder. Notes never become a proprietary database; the durable home remains local files.

02

Every write is reviewed

Research and Study notes render as a preview you approve, then write through a single-use, content-bound approval. No silent overwrite, no auto-apply.

03

MCP runs in a real sandbox

Tool calls run behind a platform-native sandbox — macOS Seatbelt, Linux bubblewrap, Windows Job Objects — with bounded I/O, not prompt-level safety.

04

Reasoning is a setting, not a leak

Choose DeepSeek, GLM, Kimi, Qwen, Ollama, or OpenRouter. Only supported reasoning levels appear; private chain-of-thought is not displayed or retained.

05

Runs are observable

Durable events, a traceable iteration view, and content-bearing checkpoints mean a run can be understood, interrupted, and recovered without losing work.

06

Desktop lifecycle is owned

The Rust shell selects a port, supervises Core, checks heartbeats, and terminates its complete process tree on exit.

FIVE-MINUTE SOURCE START

Explore first. Connect things later.

git clone https://github.com/Totoro-qaq/restork.git
cd restork
./scripts/quickstart.sh

Open the printed loopback URL and enter the one-time pairing code. You can inspect the local workspace without an API key; model-backed work requires a provider you explicitly configure, and no Vault is read unless you select one.
