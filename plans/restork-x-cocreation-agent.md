# Plan — X 共创写作 Agent（v1：只读与草稿）

> Spec: [x-cocreation-agent](../docs/specs/x-cocreation-agent.zh-CN.md)

## 为什么做

X 上有一手 AI 资讯，Restork 已经有了只读的 `x_search`。它默认走本机 Grok CLI 的 xAI OAuth，不购买 X API 资源；但 OAuth 只是认证方式，搜索仍受 Grok Build / xAI 账户额度和限流约束。若本机设置了 `XAI_API_KEY`，还可能进入 xAI API 计费。缺的不是搜索入口，是把**可核验的逐帖证据**变成「你愿意原样发出去的草稿」这一段。

v1 只解决这一段。账号是从零开始的，现在的瓶颈是文案质量，不是发布效率 —— 草稿不够好的时候，发布自动化只是在加速产出你不满意的东西。

## 不做

- 发布、删帖、回复、引用、私信 —— **永不实现**，仓库里不存在对应代码路径
- 自动点赞、批量关注、按关键词自动回复（X 明令禁止 / 需书面批准，永不实现）
- X API、OAuth、指标采集（只在可选的 v3 出现，且只申请只读权限）
- 早期指标归因与预测模型（近零粉丝阶段的方差来自「有没有被大号转」，做归因等于拟合噪声）
- X 共创切片不新增前端运行时依赖或页面框架（主题系统的 GSAP 依赖属于独立改动）
- 直接推 `main`（保护分支，走 PR + `full-ci`）

4. A4 已完成：固定 `publish.x.com/oembed`、200/404/429 语义、URL/author/schema/128 KiB 边界、超时与 endpoint 漂移全部失败关闭；公开正文覆盖模型摘要，模型续写不进入产品证据。

### 为什么 v1 不做 MCP

Restork 已经有原生 `x_search` 工具与状态接口；新增本地 MCP 只会包装同一条 Grok CLI 链路，既拿不到 xAI 不返回的服务端 tool output，也会增加进程生命周期、配置、权限和诊断面。v1 直接实现为 Restork 原生 citation 验证适配器。只有两个以上独立宿主需要复用该能力，或上游提供正式 X Search MCP endpoint 时，才另立接口 ADR。

## 之后怎么分

**v2 · 把总结做深**（不购买 X API 资源，但仍可能消耗 Grok Build / xAI 额度）

1. 雷达输出从链接列表升级为可读简报：谁发布了什么、哪个问题被反复问、哪两种说法互相矛盾。每条仍带链接，仍不下趋势结论。
2. 接上已有的 `core.reports`：最近七天标记为 `public` 的 Restork 运行 + 你手填的周摘要 → 自动周报 → 作为选题的第二个输入源。现有能力不读取 Git commit 或 GitHub PR。
3. 选题算法改为双输入：X 在聊什么 × 你这周做了什么。交集就是「开发判断」和「失败复盘」两个栏目的原料。

第 2 条是这一版真正的价值点。选题现在只看得见外面，看不见你自己。

**v3 · 效果回看**（可选，唯一需要授权）

1. X API 只读授权，只申请读权限。
2. 拉取自有帖子的曝光、主页访问、链接点击、收藏。
3. 按栏目聚合，产出复盘文档，不产出策略建议。
4. 前置门槛：已有 20 篇以上按栏目记录的帖子。不到就不做。

## 风险

- **Grok CLI 返回结构不稳定或生成占位链接。** 它是外部 CLI，结构化 schema 也不能代替真实性校验。缓解：3+7 Gate；优先解析 `structuredOutput`，仅在 CLI 明确报告结构化拼接错误时接受完整 schema JSON 序列的最后一项；逐项验证数字状态 ID、URL、账号与 Snowflake 时间一致；失败显示原因，不静默丢弃、不补猜、不伪造结果。
- **提示注入。** X 正文是任何人都能写的文本。缓解：v1 根本没有写入 X 的代码路径，加上 XCO-003 的注入测试。这是「不实现」比「实现后禁用」更安全的典型例子。
- **风格档案被噪声污染。** 缓解：3 次同向修改的门槛 + 每次写入都要你确认 + 它是一份你能直接删的普通 Markdown。
- **范围膨胀回六页方案。** 缓解：Spec 的「不在本 Spec 内」与「永不实现」是硬边界。v2 只做总结，v3 可选且只读；发布类能力已从路线图里彻底移除，不是推迟。
