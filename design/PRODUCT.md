# Restork 产品定义

> 状态：产品与体验基线  
> 适用范围：Restork 桌面端、Dashboard、Core 及其公开产品表达  
> 当前体验参考：`restork-shell-redesign-v3.html`  
> 更新日期：2026-08-16

## 1. 一句话定位

Restork 是一个本地优先的 AI 桌面工作台，把查资料、学知识和推进工作放进同一条可回看、可审批、可复用的任务链路。

它不以“聊完一次”为终点，而是让一次任务留下清楚的来源、过程、决定和交付物，之后还能继续使用。

## 2. 产品要解决的问题

知识工作常被拆散在聊天窗口、网页、Markdown 笔记、任务清单、模型工具和导出文件之间。用户不仅反复解释背景，也很难回答：

- 这次任务现在做到哪里；
- 结论基于哪些来源；
- 模型或工具准备修改什么；
- 哪些动作已经发生，哪些仍在等待确认；
- 结果能否沉淀为笔记、任务、报告或演示文稿；
- 中断、刷新或失败后，是否还能从原位置继续。

Restork 的核心机会不是增加另一个聊天界面，而是把“提出目标—执行—复核—保存—复用”做成一条值得信任的本地工作流。

## 3. 产品承诺

用户用一句话发起一件需要几分钟完成的事。Restork 负责组织上下文、记录步骤、显示来源与状态，并在任何写入或外部副作用发生前，把具体影响交给用户确认。完成后，结果成为可以继续编辑、下载、追溯或再次使用的本地资产。

这项承诺由五个可见行为组成：

1. **一句话开始任务**：默认入口是任务，不是空白聊天框。
2. **过程看得见**：阶段、轮次、工具、来源、预算、重试和失败都有记录。
3. **改动先预览**：写入文件、应用任务变更或导出敏感内容前展示具体差异。
4. **控制权属于用户**：Provider、知识库、连接、扩展和自动化都由用户显式启用。
5. **结果可以继续使用**：研究、学习和工作结果能进入笔记、任务、报告、演示文稿或下一次运行。

## 4. 目标用户

### 4.1 独立开发者与工程师

在代码、文档、GitHub 项目、技术文章和会议记录之间持续切换，希望把技术调研、实施计划、任务、周报和交付物放进同一条可追溯流程。

### 4.2 研究者、学生与长期学习者

需要区分“模型说了什么”和“来源实际支持什么”，也需要把本地笔记转成学习路径、无答案练习和后续复习行动。

### 4.3 产品、咨询与其他知识工作者

需要从多份资料形成计划、报告、交接或演示文稿，同时希望敏感文件留在本机、长期背景不必反复粘贴。

### 4.4 首批重点用户

- 长期维护 Obsidian 或普通 Markdown 知识库的人；
- 关注本地优先、隐私和可审计 Agent 的开发者；
- 做 AI Agent、MCP、桌面工具和开发者体验的开源作者；
- 愿意用真实工作流反馈产品，而不只比较模型回复质量的人。

## 5. Restork 不是什么

- 不是“模型最多”的聊天客户端；
- 不是远程多人协作平台；
- 不是密码管理器或操作系统级安全沙箱；
- 不是无需确认即可自治执行的编码、部署或消息代理；
- 不是把 Markdown 锁进私有数据库的笔记应用；
- 不是依赖用户安装编译器、脚本运行时或一组基础 Skill 才能使用的开发框架；
- 不是用卡片数量、动画光效或架构术语证明能力的通用 AI Dashboard。

## 6. 核心产品模型

Restork 围绕五个对象组织体验：

| 对象 | 用户心智 | 产品职责 |
| --- | --- | --- |
| 目标 | 我想完成什么 | 保留原始意图、模式、范围与完成条件 |
| 运行 | 这件事正在怎么推进 | 持久记录阶段、事件、预算、重试与状态 |
| 来源 | 结论依据什么 | 保存来源身份、定位、哈希、权威性与获取时间 |
| 审批 | 哪个副作用需要我决定 | 展示目标、差异、范围、版本和失效时间 |
| 交付物 | 最后得到什么 | 绑定来源运行、内容版本、格式与后续动作 |

`run_id` 是持久任务身份。HTTP 请求、SSE 连接和访问令牌都可以重建，不能决定一项任务是否存在。刷新、休眠或短暂断线后，界面应从持久事件继续，而不是重复模型调用、工具操作或文件写入。

## 7. 核心任务闭环

### 7.1 开始

默认首页只回答一个问题：**现在想做什么？**

用户输入目标，选择“查资料”“学知识”或“推进工作”，再选择已配置的模型。缺少必要连接时，就地说明缺什么并保留已输入的目标。

开始页不是仪表盘，不展示指标墙、新闻流、天气卡片或功能说明墙。首屏只保留一个主要动作：**开始任务**。

### 7.2 运行

任务创建后，用户可以看到：

- 当前阶段与最新事件；
- 已使用轮次、Token、时间或其他真实预算；
- 工具执行、来源读取、失败与重试；
- 正在等待的用户动作；
- 停止任务入口；
- 完成、失败或取消后的明确结果。

原始日志和技术细节按需展开，不默认淹没任务判断。

### 7.3 确认

当 Restork 准备写入知识库、修改任务、导出文件或执行其他有副作用的动作时，进入待确认状态。

确认界面必须回答：

- 要改什么；
- 写到哪里；
- 当前版本是什么；
- 具体差异是什么；
- 确认会产生什么影响；
- 这次确认何时失效。

一次确认只绑定当前内容与资源版本。内容或目标发生变化后必须重新预览，不能复用旧批准。

### 7.4 结果

完成后，结果进入可阅读、可复核状态。用户可以打开交付物、回看来源运行、保存到知识库、下载支持的格式，或把结果继续转成任务、学习材料、报告和演示文稿。

### 7.5 继续使用

产品价值不止是“生成成功”，还包括结果是否被采用、修改、复用和继续推进。记忆、模板、Provider、Skill、MCP 与自动化都应有清楚的来源、版本、启用状态和撤销路径。

## 8. 三种工作模式

三种模式使用同一个 Core，并共用预算、事件、审批、恢复、记忆和本地 Dashboard。它们不是三个互相争夺上下文与权限的 Agent。

### 8.1 查资料

目标：把公开资料整理为带来源、可复核的研究结果。

关键行为：

- 扫描本地索引时只记录命中数量；
- 通过统一出站网关获取受限大小的公开文本；
- 合并相同 URL 或内容哈希的重复来源；
- 主张必须绑定实际存在的证据卡；
- 推断必须标明依据；冲突必须保留不同来源；
- 研究流程本身不直接写入 Markdown，只返回新增或追加建议；
- 保存仍需独立预览与审批。

### 8.2 学知识

目标：从主题或用户选择的本地笔记出发，形成诊断、学习路径、练习和下一次复习行动。

关键行为：

- 先诊断，再生成路径；
- 只有明确位于“先修”类标题下的已解析链接才成为先修知识；
- 练习默认不泄露答案；
- 错误记录用于安排重试和间隔复习，不等同于长期掌握；
- 原始回答正文不持久化，运行状态只保留必要的哈希与结果；
- 学习记录不会自动进入长期记忆；
- 生成学习笔记时仍需预览与单次审批。

### 8.3 推进工作

目标：从用户选择的本地工作区形成计划、脱敏交接包和可核对的结果清单。

当前边界：

- Restork 读取受限文本快照并生成计划；
- 用户预览精确的脱敏交接内容后，才能导出；
- 外部执行器由用户单独启动；
- Restork 可以核对返回清单中的文件哈希与声明范围；
- 当前版本不运行 Shell，不启动 Codex，不修改仓库，不推送 Git，不部署，也不发送消息；
- Restork 未亲自执行的命令只能标为“未验证”，不能伪装成已验证结果。

## 9. 信息架构

当前 v3 外壳将导航收敛为三个组，减少首层概念数量。

### 9.1 核心

| 页面 | 第一任务 | 关键内容 |
| --- | --- | --- |
| 开始 | 发起一项新任务 | 目标输入、模式、模型、必要连接状态、首次示例 |
| 仪表盘 | 理解今天与当前工作 | 本机时间、可选天气、日历、每日一曲与工作上下文 |
| 运行 | 判断做到哪里、是否需要我处理 | 状态筛选、运行列表、过程、来源、交付物、审批 |
| 任务 | 管理本机待办 | 新建、完成、删除、恢复与可选知识库同步 |
| 对话 | 回看或继续会话 | 会话列表、固定模型、消息、导出与归档 |

### 9.2 知识

| 页面 | 第一任务 | 关键内容 |
| --- | --- | --- |
| 知识库 | 查找并阅读本地内容 | 搜索、文件列表、安全 Markdown 预览、来源提示 |
| 交付物 | 找到可以继续使用的结果 | 需求摘要、内容预览、来源运行、下载与版本 |

### 9.3 本机

| 页面 | 第一任务 | 关键内容 |
| --- | --- | --- |
| 自动化 | 看清何时会做什么 | 计划、时区、任务类型、立即运行、暂停与历史 |
| 设置 | 调整本机行为与连接 | 个人、模型、知识库、更新和关于 |

### 9.4 仍属于完整产品的能力

Radar、记忆、扩展、审批中心、报告与演示文稿等能力仍属于完整产品。当前 v3 原型没有把所有能力都放进一级侧栏：

- 审批优先进入运行上下文，减少用户在两个页面之间来回判断；
- Radar 与每日上下文先作为仪表盘摘要，再按实际使用频率决定是否保留一级入口；
- 记忆与扩展需要独立的可检查、可禁用、可回滚管理面，后续不应被简化成静态设置卡；
- 报告、PPTX、PDF 与 Markdown 由交付物统一承接，不在开始页堆叠格式选项。

这些是信息架构方向，不代表生产功能已被删除。

## 10. 关键页面体验

### 10.1 开始页

- 问候克制，标题保持产品尺度；
- 输入区是任务创建器，不伪装成即时聊天；
- 三种模式使用单选语义并支持键盘操作；
- 模型只出现在输入区，不在状态行重复；
- 没有进行中任务、待确认事项或连接问题时，状态行整行不出现；
- 示例只服务首次成功运行之前，之后折叠但仍可找到；
- 创建中防止重复提交；失败时保留用户输入。

### 10.2 仪表盘

仪表盘回答“今天与当前工作是什么”，不重复开始页的输入器。

每日上下文是可选连接，不是产品启动前置条件：

- 本机日期与时间无需联网；
- 天气需要用户主动配置位置，不通过 IP 猜测；
- 日历只读，未连接时仍显示本机日期；
- 每日一曲只读取用户主动连接的公开歌单或本地文件，不接收账号密码、Cookie、音频或歌词；
- 没有可靠依据时，产品明确说不知道，不编造推荐原因。

### 10.3 运行详情

运行采用“列表 + 详情”结构，详情包含过程、来源与产物三个稳定分区。运行中场景可以局部使用更强的视觉表达，但不能让状态判断依赖动画或颜色。

待确认动作直接嵌入来源运行，用户能同时看到任务目标、最新阶段和具体差异。拒绝、过期或停止后，界面说明哪些内容没有被改动、哪些记录仍被保留。

### 10.4 任务

- 本机任务可以直接编辑；
- 删除进入可恢复区域；
- 模型建议的任务必须标明来源和确认状态；
- 与 Markdown 同步前先显示差异，确认后才写入；
- “没有任务”是正常状态，不用警示色制造焦虑。

### 10.5 对话

- 对话是辅助入口，不是默认首页；
- 每次会话明确绑定模型，不允许后台隐藏回退；
- 换模型继续时创建分支，并预览将带过去的上下文；
- 私有消息不能被发送给权限范围不合适的模型；
- 支持搜索、导出、归档和恢复，但不把私有内容留在浏览器存储。

### 10.6 知识库

- 用户主动选择目录，Restork 不自动扫描私人 Vault；
- 文件列表与预览独立滚动；
- 支持名称、路径、标签与正文检索；
- Markdown 以惰性、安全方式渲染，内嵌 HTML 与脚本不执行；
- 绝对路径不进入网页界面或公开产物；
- 写入始终走预览、审批和版本绑定。

### 10.7 交付物

- 每个交付物绑定来源运行与内容版本；
- 用户先看需求摘要、大纲或页面预览，再选择模板与格式；
- 支持的 Markdown、无宏 PPTX 与 PDF 由安装包提供基础能力；
- 预览和下载是真实动作，不放假按钮；
- 不把“文件已生成”当作质量完成，仍需内容、来源和格式校验。

### 10.8 自动化

- 计划按本机时区触发并正确处理夏令时；
- 模型起草类自动化需要明确同意联网与可能费用；
- 只发送标记为 `public` 的运行事实；
- 草稿保留在本地并等待用户过目；
- “立即运行”也不能跳过写入确认；
- 支持暂停、历史和恢复，不把技术 ID 暴露为主要输入。

### 10.9 设置

设置按“个人、模型、知识库、关于与更新”分组，不一次铺满所有配置。

- 称呼、语言、时区、主题和启动页只留在本机；
- Provider 与精确模型绑定，不允许隐藏回退；
- 云端 Key 进入系统原生凭据库，不进入网页表单、SQLite、日志、命令行参数或浏览器存储；
- 更新首次启动不检查，之后轻量提醒；下载、安装和重启是独立动作；
- 有运行、文件写入、审批或导出时，不允许安装更新。

## 11. 信任、隐私与安全边界

### 11.1 数据所有权

| 数据 | 权威来源 | 默认位置 |
| --- | --- | --- |
| 笔记与 Markdown 任务 | 用户选择的 Vault | 普通本地文件 |
| 运行、审批、事件与副作用记录 | Restork Core | 私有 SQLite |
| 工作检查点 | Core | 加密且有 TTL 的临时数据 |
| 稳定偏好与可检查记忆 | 用户与 Restork Profile | 私有本地配置 |
| Provider 凭据 | 操作系统凭据库 | Keychain / Credential Manager / Secret Service |
| 索引与链接图 | 本地可重建缓存 | 可删除后重建 |

### 11.2 网络边界

- 只有 Core 拥有公共网络能力；
- 无配置就不产生隐藏请求；
- 出站请求必须校验 HTTPS 来源、地址类别、数据分类、重定向、查询字段与字节上限；
- 凭据和秘密不能进入记忆、交接包、交付物或临时存储；
- 浏览器只收到渲染当前界面所需的字段；
- 页面刷新、SSE 重连或 Token 续期不能重复副作用。

### 11.3 审批边界

- 写入前必须展示精确内容；
- 审批绑定内容哈希、目标和资源版本；
- 审批单次使用并按时失效；
- 目标或内容变化后重新审批；
- 失败、拒绝或取消必须说明没有发生什么；
- 审计记录保留事实，不保存不必要的私有正文。

### 11.4 明确限制

Loopback 和配对不能防御同一操作系统用户权限下的恶意软件。Restork 也不把 Core 的策略包装成操作系统级隔离。产品文案必须如实说明边界，不能泛称“绝对安全”。

## 12. 产品表达与视觉系统

### 12.1 核心气质

Restork 是一张可以执行任务的编辑工作台：温暖纸张、细墨线、清楚留白、克制状态色。界面首先让人看见工作内容和下一步，不让装饰抢走判断。

### 12.2 三个视觉角色

1. **纸张工作台**：开始、知识库、任务、设置和完成结果。以一层主表面、分隔线和留白建立层级。
2. **运行暗房**：模型思考、工具执行、等待来源和等待确认的局部工作现场。只服务运行状态，不成为全局主题。
3. **确认印记**：写入、修改、导出和外部动作。具有可识别的仪式感，但操作仍使用标准按钮、焦点态和清楚文案。

表现力配额约为：80% 安静工作台、15% 真实产品证明、5% 品牌装饰与动效。

### 12.3 颜色

- 暖纸背景与深墨文字构成主体；
- 紫色表示当前选择、焦点和唯一主动作，不作装饰性光晕；
- 成功、提醒、危险和信息色的语义跨页面保持一致；
- 状态不能只靠颜色，必须同时有文字、形状或位置线索；
- 同一屏幕只保留一个主要动作，同一相邻按钮组最多一个实心按钮。

### 12.4 字体

- UI 正文与标题使用系统无衬线字体；
- 打字机字体只用于 Restork 标志、编号和极少量编辑印记；
- 等宽字体只用于数值、时间、ID、哈希、命令和技术日志；
- 不从公网加载字体，也不把字体包变成安装依赖；
- 中文不使用全大写式字距，不靠装饰字体制造层级。

### 12.5 布局

- 一级外壳为可折叠侧栏、顶部上下文栏和独立滚动内容区；
- 页面尽量只有一层主边界，内部用列表、分隔线、表格和留白；
- 真正可独立操作的对象才使用卡片；
- 超宽屏限制阅读宽度，窄屏重组内容而不是压缩桌面布局；
- 长标题、URL、日志、表格和文件路径必须有换行、截断或独立滚动策略；
- 不使用仿浏览器圆点和假窗口装饰产品画面。

### 12.6 动效

- 动效只解释进入、状态切换和等待；
- 默认 160–240ms，优先 `opacity` 与不超过 8px 的短位移；
- 旋转只服务用户主动播放的唱片等真实状态；
- `prefers-reduced-motion` 下取消位移、旋转和循环；
- 不引入大型动效运行时、WebGL 或远程资源。

## 13. 产品语气

Restork 像可靠的同事：把事实说清楚，把下一步放在手边，不用官僚腔或拟人化噱头。

- 自称“Restork”，称用户“你”；
- 空状态说明现状，再给一个带动词的下一步；
- 等待说明正在做什么、结果会出现在哪里；
- 出错先说明没丢什么，再说下一步；
- 涉及花钱、删除、授权、切换知识库和写入时，冷静说明范围与后果；
- 完成可以有一点温度，但不使用夸张庆祝；
- 不显示内部枚举、数据库字段或无意义技术缩写；
- 不编造来源、指标、效率提升、用户评价或“为什么流行”。

## 14. 可访问性与交互基线

- 所有可聚焦元素具有清楚的 `:focus-visible`；
- 键盘可以完成导航、筛选、切换页签、打开和关闭弹层、审批与命令面板；
- 弹层关闭后焦点回到触发点，隐藏区域不接收焦点；
- 触屏目标优先不小于 44px；
- 正常正文对比度至少 4.5:1，大字与图标至少 3:1；
- hover、active 和 selected 状态不降低文字对比度；
- 状态更新使用局部 `aria-live`，不重复朗读整页历史；
- 正文基准 16px，辅助信息不低于 12px，浏览器缩放 200% 时不裁切；
- 目标断点至少覆盖 320、375、414、768、1280、1440 与 1920px，无横向滚动；
- 动画关闭后，所有信息和操作仍然完整。

## 15. 成功指标

这些指标用于判断产品是否真正减少了任务摩擦，不以 Star 或功能数量代替价值：

- 首次启动到成功完成第一个 Run 的时间；
- 选择知识库、配置 Provider 和保存凭据时的退出率；
- Run 完成率、恢复率、失败率与待确认超时率；
- 重连后重复调用或重复副作用的数量，应为零；
- 研究结论的来源覆盖、冲突保留和去重情况；
- 结果被保存、下载、修改、复用或转成下一项任务的比例；
- 交付物被采用后需要修改的范围；
- 一周后再次打开并继续真实任务的比例；
- 用户新增或修改模板、Skill、自动化和模型配置的比例；
- 安装、启动、更新和恢复失败的数量；
- 普通用户必须阅读终端教程或安装额外运行时的次数，应持续下降。

具体数值目标应在获得真实基线后设定，不能由原型或合成数据推断。

## 16. 交付与验收门槛

### 16.1 产品门槛

- 开始页默认只保留一个主要决策；
- 运行、来源、审批和交付物可以完整追溯；
- 任何写入都有精确预览、版本绑定与显式批准；
- 中断和重连不会重复付费调用、工具动作或副作用；
- Provider、知识库、天气、日历、邮件、歌单和自动化都默认关闭或按需启用；
- Work 不越过“计划、脱敏交接、结果核对”的当前边界；
- 演示和公开素材只使用合成数据；
- 构建成功、预览成功或安装包生成成功不能替代真实 Core 启动与完整任务验证。

### 16.2 体验门槛

- 主要区域最多一层纸卡边界，嵌套卡片必须有独立操作理由；
- 不使用功能卡墙代替任务叙事；
- Run、Approval 与 Deliverable 各有可识别但不冲突的产品场景；
- 所有主要控件具备默认、hover、focus、active、disabled、loading、error 和 success 状态；
- 窄屏、桌面、超宽屏与 200% 缩放没有遮挡、裁切或横向滚动；
- 中文与英文分别使用对应素材，并提供静态与 reduced-motion 方案；
- 不新增无必要的前端运行时、在线字体和装饰性媒体依赖。

### 16.3 运行门槛

- 新安装的桌面应用能启动真实 Restork Core；
- Dock、开始菜单或桌面入口启动后的环境与开发终端一致可用；
- 能完成一次真实任务、事件续传、审批和结果打开；
- 安装、退出、卸载、更新与恢复在目标平台上通过干净环境验证；
- 未签名技术预览必须如实标注，不能用“正式版”语气掩盖签名与公证状态。

## 17. 当前 v3 原型的验证范围

`restork-shell-redesign-v3.html` 是高保真交互原型，用于验证外壳、开始页、每日上下文和关键工作流表达。它包含：

- 可折叠侧栏与九个主要视图；
- 浅色、深色与跟随系统主题；
- 开始任务、模式切换、状态提示和首次示例；
- 仪表盘的天空仪、天气位置、日历和每日一曲连接反馈；
- 运行筛选、过程、来源、产物、停止与写入确认；
- 本机任务、最近删除与知识库同步说明；
- 会话创建、固定模型、消息列表与导出；
- 知识库搜索、安全预览与不受信任内容提示；
- 交付物、自动化、设置和命令面板；
- 交付物创建：手写报告、AI 起草近期运行、演示文稿大纲与六套内置版式（含自定义版式的新建、导入与回收站）；
- 键盘焦点、Esc 关闭、`Cmd/Ctrl+K`、reduced-motion 与响应式处理。

原型中的运行、天气、来源、任务、会话和版本号是明确标注的合成或示例数据，不代表真实生产状态。原型为了演示会把视图、主题、侧栏和称呼写入 `localStorage`；生产产品不得照搬这条实现，生产偏好与私有内容必须继续遵守 Core、原生壳和隐私规范。

## 18. 近期产品优先级

1. **验证第一条真实闭环**：开始一项查资料任务，查看来源与进度，检查写入差异，得到一篇可继续编辑的本地笔记。
2. **验证桌面启动与恢复**：从真实安装入口启动 Core，完成配对、运行、断线续传、退出与再次打开。
3. **统一运行与审批体验**：减少重复入口，让待确认动作始终带着目标、来源和差异上下文。
4. **提升交付物质量可比较性**：记录采用、修改、复用与来源完整度，而不只记录生成成功。
5. **根据真实使用收敛导航**：观察任务、Radar、记忆、扩展和审批中心的使用频率，再决定一级入口归属。
6. **完成跨平台发布信任链**：签名、公证、校验、更新所有权和干净机器验收完成前，继续如实标注技术预览。

## 19. 待验证问题

- 首次用户能否在一分钟内理解 Restork 与普通聊天客户端的差异；
- “运行内审批”是否足够，还是高频用户仍需要独立审批中心；
- 任务是否应继续作为一级入口，或逐步并入仪表盘；
- Radar、记忆和扩展在真实使用中的入口频率与最佳层级；
- 每日上下文能否帮助进入工作状态，而不会稀释核心任务链；
- 用户最愿意长期复用的是研究笔记、学习材料、任务、周报还是演示文稿；
- 当前信息密度是否同时适合初次用户与需要审计细节的高级用户；
- 三平台安装、首次配置和更新流程中，哪一步最容易造成放弃。

## 20. 决策原则

遇到新功能、视觉提案或架构选择时，按以下顺序判断：

1. 是否帮助用户完成真实任务；
2. 是否让过程、来源和副作用更容易理解；
3. 是否保留本地文件所有权和显式控制；
4. 是否能在中断、失败和更新后恢复；
5. 是否让结果更容易复用与比较；
6. 是否增加普通用户的安装、配置或理解成本；
7. 如果只是让界面“更像 AI 产品”，则不做。
